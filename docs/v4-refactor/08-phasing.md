排序理由：

0. **M1/M2 的边界是「数据模型草稿 → reducer 锤炼 → 冻结 → 补传输外壳」**（2026-07-05 修正）：协议分两半——数据模型（snapshot/row/delta，即 reducer 的输出类型）和传输外壳（帧/订阅/命令信封）。数据模型必须先于 reducer 存在，但冻结必须后于 reducer 验证；传输外壳只需赶在 M3 通道层开工前就位。避免 schema-first 瀑布把类型闭门冻错。
1. **M2 在任何删除之前**是安全带——黄金测试全绿意味着新事实源已被证明正确，不存在「删了旧的、新的不知道对不对」的悬空期。
2. **黑暗期只有 M3–M4**（桌面 chat 在分支上不可用），M0–M2 期间 main 随时可正常发版修 bug。
3. **手机/web 最后动**，符合 web 远控保护约束；手机 App 在 M4 合并后即可启动——它只是又一个投影渲染器。
4. **分屏放 M5**：不是风险项，是新 store 的第二个消费者，不挤占竖切的验证精力。
